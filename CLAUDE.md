## What this is

colonIA (HackADA hackathon): a map of CDMX neighborhood commerce. A voice note to a Telegram bot registers a business; an LLM only **extracts fields**, while every number and route is deterministic code. Every figure carries `tipo_dato` (`real` | `estimado` | `simulado`) — preserve this traceability when adding data or endpoints. UI and domain text are in Spanish.

## Commands

```bash
uv sync                                   # Python 3.12 deps (uv)
DEMO_MODE=1 bash scripts/demo.sh          # full app on :8000, no keys/network (recorded responses); builds web, seeds demo repartidor
bash scripts/demo.sh                      # same, but uses keys from the env file and starts the Telegram bot if a token exists
uv run uvicorn app.main:app --reload      # API only (serves web/dist if built)
uv run python -m app.bot                  # Telegram bot (long polling)
uv run pytest                             # all tests (app/tests, pipeline/tests); config in pyproject.toml
uv run pytest app/tests/test_x.py::test_y # single test
uv run ruff check .
npm --prefix web ci && npm --prefix web run dev     # Vite dev server
npm --prefix web run build                # tsc -b && vite build -> web/dist
npm --prefix web run lint                 # oxlint
npm --prefix web test                     # node --test (hex.test.ts)
uv run python scripts/simular_alta.py --caso dona-lupe --url http://127.0.0.1:8000   # simulate a voice-note signup without Telegram
```

In this kit, run tests via `bash .uak/bin/q <cmd>` and use `$UAK_PORT` / `$UAK_PORT+1` instead of hard-coded ports (see AGENTS.md). Secrets live only in the git-ignored env file; all keys and model IDs are read through `app/config.py` (`settings`) — never hard-code them elsewhere.

## Architecture

- **Backend (`app/`)**: FastAPI. `app/main.py` auto-discovers every module in `app/routers/` that exposes a `router` (no manual registration — adding a file adds the routes). Routers are thin; logic lives in `app/services/` (same-named modules: `altas`, `mapa`, `ruta`, `repartidores`, `ofertas`, `crecimiento`, …). `app/schemas/` holds Pydantic models. The built frontend (`web/dist`) is mounted at `/` **last**, so `/api/*` and `/n/*` take precedence over static files.
- **Telegram bot (`app/bot/`)**: separate process (`python -m app.bot`) for business owners (voice-note signup) and repartidores; shares `app/services`.
- **`DEMO_MODE`** (`settings.demo_mode`): replaces LLM/transcription/Mapbox calls with recorded fixtures in `app/fixtures/` and `app/bot/fixtures/` — the plan B for the demo. New LLM-dependent features need a fixture path too.
- **Data pipeline (`pipeline/`)**: offline builders (DENUE, geo/H3 hexes, negocios, articulos, reales) that produce `data/processed/*.json|geojson`, which the services read at runtime. `data/fuentes/*.md` documents provenance of each dataset; `data/demo/plataforma_simulada.json` is simulated history (generated by `scripts/generar_historia.py`, labeled `simulado`). Runtime-written state goes under `data/live/`.
- **Frontend (`web/`)**: Vite + React 19 + TypeScript + Tailwind v4 + Mapbox GL + h3-js. Hash-routed single page (`#/sedeco`, `#/usuario`, `#/negocio`, `#/repartidor`); one folder per role/screen in `web/src/features/` (`inicio`, `mapa`, `negocio`, `repartidor`, `usuario`), shared code in `web/src/lib/` (`api.ts`, `types.ts`, `map/`, `ui/`). Visual rules are in `web/DESIGN.md`. Needs `VITE_MAPBOX_TOKEN` (without it the base map doesn't draw; panels still work).

## Conventions worth knowing

- Domain config (alcaldías prioritized `09003,09007`, DENUE SCIAN/strata filters, repartidor priority weights) is in `app/config.py` and comes from `IDEA-v2.md`; check that file for product intent before changing business rules.
- Never edit an existing test to make it pass; tasks restrict edits to their declared `Paths` (see AGENTS.md).
